# WuxiaRAG
武侠小说知识库系统
## 项目目标
练习学到的RAG知识,熟悉LangChain框架，构建一个智能的武侠问答系统。
用户可以得到以下类似问题的回答：
1. 事实查证与“考据党”福音（最擅长）
精准定位：“乔峰在少室山上，用一招‘亢龙有悔’打向了谁？”（RAG会直接定位到原文段落并给出答案：丁春秋）。
冷门细节：“段誉在无量山洞里磕了一千个头，是向谁磕的？”（答案是“神仙姐姐”的玉像）。

2. 情节逻辑与因果梳理（“连线”高手）
跨章节把散落的信息串联起来，帮你理清复杂的前因后果：
动机分析：“慕容复为什么一心要复国？小说里提到了哪些具体原因和背景铺垫？”（RAG会检索出关于他家族背景、与西夏/大辽关系等的所有相关描述）。
过程复盘：“虚竹是如何一步步解开‘珍珑棋局’的？现场都有谁出手干预了？”

3. 人物行为与性格深度挖掘（多维画像）
不再泛泛而谈“乔峰很猛”，而是基于小说原文给证据：
特定反应：“乔峰在面对‘他是契丹人’这一身份被揭穿时，他的心理活动和外貌描写有哪些变化？”
对比分析：“段誉对王语嫣的痴情，和游坦之对阿紫的痴情，小说原文中对这两种‘痴’的描写有什么异同？”

4. 武功体系与战斗复盘（“设定集”查阅）
原理探究：“‘北冥神功’吸人内力的具体条件和副作用，原著里是怎么写的？”
实战复盘：“鸠摩智在天龙寺以一敌六时，分别用了什么武功，六脉剑阵是如何运转的？”

5. 辅助创作与同人灵感（“不违背原著”的顾问）
时间线校准：“我想写乔峰和阿朱相识初期的同人，原著中他们在雁门关相遇时是几月份，天气如何？”
台词还原：“原著里玄慈方丈临死前说的最后一句话是什么？我想在我的解读文章里准确引用。”


## 技术框架
1.使用LangChain框架，然后代码结构参考 https://datawhalechina.github.io/all-in-rag/#/ 第八章
2.调用PDFMuxLoader处理PDF，使用FAISS 构建向量索引，底层大模型用的Deepseek
3.使用双检索器 BM25 + 向量，分拆多路检索，并根据权重融合RRF，融合后的检索结果再经过大模型重排。
采用了“小块检索、大块生成”，保证内容的丰富性。

以下是检索的流程：
用户 query
  ├─ 路1 去噪原问       → 向量检索
  ├─ 路2 HyDE 假设原文   → 向量检索
  ├─ 路3 场景同义词改写  → 向量/BM25 检索
  └─ 路4 共现实体扩展    → 向量/BM25 检索
        ↓
   加权 RRF 融合（每路权重不同）
        ↓
   Cross-encoder / LLM 重排
        ↓
   top_k

## 运行说明

pip install -r requirements.txt

3.运行main.py即可,测试问题 可以看 上面的《项目目标》，还可以用tests文件夹中的test_question里面的问题进行测试


## 设计思路
小说属于非结构化文档，可以以章节为单位分割，每个章节大约上万字，需要再进一步分块。
分块策略：“章节感知”的递归分块
核心思想是：先利用章节作为天然的语义边界，再对每个章节内部进行精细分块。
第一步：按章节加载：因为武侠小说的PDF，不包含复杂的表格，页数比较多，希望处理速度快一些，而且是个人使用，所以选择 用LangChain的 调用langchain-pdfmux 处理PDF 加载小说。
因为目前是纯文字版本的PDF，所以 langchain-pdfmux 安装的是不含ocr的，这样依赖包较小
将每一章里面的一个大块（2000字左右）作为一个独立的 Document 对象。

第二步：章节内递归分块：对每个 Document 对象，使用 RecursiveCharacterTextSplitter 进行切分。

如何检索：
    采用父子文本块的策略：用小的子块进行精确检索，但在生成时传递完整的父文档给LLM。 这种设计是"小块检索，大块生成"——用小块的精确性找到相关内容，用大块的完整性保证回答质量。
